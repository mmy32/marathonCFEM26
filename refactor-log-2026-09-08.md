# Refactor Log — 2026-09-08

## Summary

Reorganized `2026 Extension/` (the actively-maintained pipeline) from a flat
23-file directory into a layered structure separating library code,
orchestration scripts, notebooks, docs, generated outputs, and presentation
decks. `archive 2025 version/` (a frozen, self-contained snapshot untouched
since a single archiving commit, per `git log`) was intentionally left alone,
as were root `README.md` and `.gitignore`.

Folders created inside `2026 Extension/`: `src/`, `scripts/`, `notebooks/`,
`docs/`, `outputs/`, `presentations/`. All 30 files that previously sat flat
in `2026 Extension/` were relocated into one of these via `git mv`, so git
history is preserved for every file (confirmed: `git status` shows every
move as a rename, none as delete+add). No file was renamed — only moved.

The codebase relies entirely on bare, flat local imports (`from bdc import
...`, `from paths import ...`) made resolvable via a `sys.path` hack that
assumed "my own directory contains all the sibling modules." Splitting the
files into subfolders broke that assumption, so 7 files required a small,
mechanical code edit to their `sys.path` bootstrap as a direct consequence of
the move — every one of those edits is listed below. No `from X import Y`
statement's text was changed anywhere; only the `sys.path` setup that makes
those statements resolvable was adjusted.

### Why this layout

- `src/` — every importable library module (business/data logic). No
  dedicated `config/` folder was created for `paths.py`: it's an actively
  imported code module, not static config data, and there's no secrets file
  anywhere in the repo to separate out (`get_seniority_debttype.py` reads
  `ANTHROPIC_API_KEY`/`ANTHROPIC_WORKSPACE_ID` straight from `os.environ`).
- `scripts/` — the 5 `run_*.py` entry points (orchestration layer). This
  includes `run_ixbrl_pipeline.py`, which despite having no `__main__` block
  (it's really a library function, `run_pipeline()`) is grouped by naming
  convention with its `run_*` siblings for consistency.
- `notebooks/` — the editable/source notebook.
- `docs/` — the four pipeline READMEs, colocated with the pipeline they
  document rather than moved to a repo-wide docs location.
- `outputs/` — things that are *generated by* running the pipeline rather
  than source: the two run logs, the plots folder, and the "executed" copy
  of the notebook (a frozen run record with baked-in output images, not
  something meant to be re-edited).
- `presentations/` — the two `.pptx` decks, unrelated to the code pipeline.

No `tests/` folder was created: no test file exists anywhere in the repo
today, so fabricating an empty `tests/` directory would misrepresent test
coverage rather than reflect it — this is a pre-existing gap, not something
this reorg fixes.

## Import / bootstrap edits (all caused directly by the moves)

**`src/paths.py`** — `ROOT` previously assumed the file sat directly in
`2026 Extension/`. Moving it one level deeper into `src/` requires bumping
the parent-directory count by one, or every path derived from `ROOT`
(`DATA_DIR`, `CACHE_DIR`, `PROCESSED_DIR`, the `IXBRL_*` dirs) would silently
resolve to `src/data/`, `src/cache/`, etc. instead of `2026 Extension/data/`,
`2026 Extension/cache/`:
```python
# before
ROOT = Path(__file__).resolve().parents[0]   # final/
# after
ROOT = Path(__file__).resolve().parents[1]   # 2026 Extension/
```
Verified at runtime post-move: `paths.ROOT` now correctly resolves to the
`2026 Extension/` directory.

**`scripts/run_bdc_universe.py`, `scripts/run_downloader.py`,
`scripts/run_ixbrl_parser.py`, `scripts/run_preprocessor.py`** — each had an
identical bootstrap that added its own directory to `sys.path` (which used
to also be where `bdc.py`/`filings.py`/`paths.py`/etc. lived):
```python
# before
ROOT = Path(__file__).resolve().parents[0]  # final/
sys.path.append(str(ROOT))
# after
ROOT = Path(__file__).resolve().parents[1]  # 2026 Extension/
sys.path.append(str(ROOT / "src"))
```
Every `from bdc import ...` / `from paths import ...`-style line below this
in each file is unchanged text — only the sys.path target changed. Verified
via `importlib.util.find_spec` from each script's new location that all
local module names now resolve to their `src/` location.

**`scripts/run_ixbrl_pipeline.py`** — previously had *no* bootstrap at all
(it worked only because it sat in the same flat folder as `ixbrl_utils.py`).
Added, immediately before its `from ixbrl_utils import (...)` block:
```python
import sys
from pathlib import Path

ROOT = Path(__file__).resolve().parents[1]  # 2026 Extension/
sys.path.append(str(ROOT / "src"))
```

**`notebooks/index_construction_pipeline.ipynb` and
`outputs/index_construction_pipeline_executed.ipynb`** — in both notebooks,
the bare-import cell previously ran *before* the sys.path-bootstrap cell, and
only worked because Jupyter's default working directory happened to equal
`2026 Extension/`; the bootstrap cell's own `try/except Path(__file__)` logic
always hit the `except` branch (`__file__` is never defined inside a
notebook), making it a no-op in practice. Fixed by swapping the two cells so
the bootstrap now runs first, and rewriting its body:
```python
# before (ran second; effectively a no-op)
try:
    ROOT = Path(__file__).resolve().parents[1]
except NameError:
    ROOT = Path.cwd()
sys.path.append(str(ROOT))

# after (now runs first)
import sys
from pathlib import Path

ROOT = Path.cwd().resolve().parents[0]  # 2026 Extension/
sys.path.append(str(ROOT / "src"))
sys.path.append(str(ROOT / "scripts"))
```
The import cell's text (`from run_bdc_universe import run_bdc_universe`,
..., `from get_seniority_debttype import *`) is byte-for-byte unchanged —
only its position relative to the bootstrap cell moved. Verified via
`importlib.util.find_spec` simulating each notebook's new working directory
that every local module it imports resolves correctly.

## Intentionally left unchanged (and why)

- **`archive 2025 version/`** — frozen since a single archiving commit, with
  no active collaborators touching it; reorganizing dead code adds git churn
  for no benefit.
- **Root `README.md` and `.gitignore`** — no reason to touch them for this
  move.
- **`src/ixbrl_utils.py` (1407 lines)** — the largest file in the repo, and
  it internally redefines `TERM_COLS`/`AMOUNT_COLS` twice within itself
  (once near the top, again partway through). Flagged as a candidate for a
  future split under the "minimize file size/complexity" principle, but not
  split here — that's a behavior-risking content change, not a file move.
  `src/get_seniority_debttype.py` (807 lines) and `src/index_construction.py`
  (725 lines) are similarly large and flagged, not split.
- **`src/preprocessor.py` vs. `src/ixbrl_utils.py`** — both independently
  define `classify_context()`, `normalize_interest_columns()`, `TERM_COLS`,
  and `RATE_RANGE`, with values that have drifted apart (e.g. `RATE_RANGE`
  is `(0.02, 0.50)` in one and `(0.00, 0.50)` in the other), and neither
  module imports the other. This is a pre-existing correctness risk worth
  the team's attention, but fixing duplicated logic is a separate task from
  a structural reorg and was left alone.
- **`docs/README_1.md`** — references a `run_download.py` filename (the
  actual file is `run_downloader.py`) and describes an old `src/`/`scripts/`/
  `final/` split that didn't exist until this reorg. Left as-is; correcting
  prose is outside the scope of a file-structure move.
- **`src/preprocessor.py`'s `try/except` import fallback** — both branches
  import the exact same thing, making the fallback a no-op; unrelated to
  file location and left alone.
